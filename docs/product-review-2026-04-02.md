# Open Interview 产品审视（2026-04-02）

- doc_type: product_review
- audience: product / maintainers
- status: snapshot
- created_at: 2026-04-02
- follow_up: `docs/product-review-execution-2026-04-02.md`

> 基于当前仓库代码与文档的产品角度审视，聚焦可优化、可迭代、可改进的方向。

---

## 1. 用户旅程与首次体验

- 首页直接 redirect 到 `/import`，新用户缺少"这是什么、能做什么"的 landing 引导。第一次打开就看到空的导入页，认知负担偏高。建议：当系统无数据时，展示一个轻量引导卡片说明核心流程（导入→审核→题库→练习→AI 问答）。
- 导入完成后到审核队列的衔接靠按钮跳转，没有主动通知机制。异步解析完成后用户可能不知道该去审核。nav 上已预留 `badge` 字段但未启用——启用 Review Queue 的 `needs_review` 计数即可解决。

## 2. 题库作为核心资产的深度不够

Question Bank 是文档里反复强调的"有数据后的默认主页"，但目前 `/questions` 的体验偏"列表查看"，缺少让用户主动回来的理由：

- 题目详情页缺少"自测"入口，无法直接从当前题开始练习
- 题目间的关联浏览（相关题目、同来源题目）在列表层面没有体现，只在 QA 的 citation 里出现
- 答案质量标记缺失——用户审核完答案后，没有"这个答案我满意 / 需要补充"的反馈闭环
- 题库有数据后应考虑将默认 landing 从 `/import` 切换到 `/questions`

## 3. Practice 模块的留存设计

随机练习和模拟考试已落地，但缺少"为什么要再来一次"的钩子：

- 没有错题本 / 收藏夹。做完考试看到弱项，但没有快速入口"只刷这个维度的题"
- 长期画像雷达图是好设计，但缺少趋势视图——用户看不到"上周 vs 这周"的进步
- 考试历史列表只有快照，没有对比视图
- 建议：弱项维度一键进入定向练习，历史画像叠加趋势线

## 4. QA 对话的实用性

QA 模块的 grounded answer + citation 设计扎实，但有体验缺口：

- 回答是纯文本渲染（`whitespace-pre-wrap`），不支持 markdown。AI 回答包含列表、代码块、加粗等格式时显示为原始文本
- prompt suggestions 硬编码四条，不会根据用户题库内容动态生成
- 缺少"从题库某道题直接发起 QA"的快捷路径（`ui-flows.md` 设计了 Question Bank → AI Review 流程，但代码未实现）
- 多轮对话中没有"引用上一轮回答继续追问"的交互辅助

## 5. 面经→题库的沉淀闭环

- Interview question 和 Question bank 的解耦设计合理，但 promote/merge 的操作入口不够显眼。用户在面经详情页看到好题，沉淀到题库的路径需要更明确的 CTA
- 面经列表缺少按公司、轮次的聚合视图。面经数量增多后纯列表难以浏览
- 建议：面经详情页每道题旁加"沉淀到题库"按钮，面经列表加公司分组折叠

## 6. 简历深挖的完整度

- Resume 模块相比其他模块明显更早期——存在多个 placeholder 组件，deep dive session 交互基础
- 如果"不只是刷题，还能练项目表达"是差异化卖点，值得优先补齐：
  - 项目深挖的 coach hints 交互
  - mock interview 的完整评分与反馈
  - 项目亮点的结构化编辑

## 7. 全局体验细节

- 没有全局搜索。top bar 设计预留了但未实现。题库达到几百道时跨模块搜索是刚需
- 没有键盘快捷键。workbench 产品的 power user 会期望基本导航快捷键
- 时间显示不统一——部分用 `Intl.DateTimeFormat`，部分用字符串替换 `replace("T", " ")`
- 移动端适配标注为 non-goal，但部署在公网（`career.mimiruku.cn`）后手机访问体验不应完全崩掉，至少保证可读

## 8. 数据安全与可持续性

- SQLite 单文件数据库，未见备份策略。对于"可持续积累"的系统，数据丢失是最大风险
- 没有数据导出功能。用户投入大量时间整理的题库，应能导出为通用格式（JSON / Markdown / Anki）
- 建议：至少加一个定时 SQLite 备份脚本，以及题库 JSON 导出 API

---

## 总结

主链路和架构设计成熟度高。当前最大的产品杠杆不是加新功能，而是把已有功能之间的衔接做得更顺滑，让用户形成"导入→整理→练习→回顾"的日常习惯。

优先级建议：
1. Review Queue badge + 题库动态 landing（低成本高感知）
2. QA markdown 渲染 + 题库→QA 快捷路径（核心体验补齐）
3. 错题本 / 维度定向练习（留存钩子）
4. 数据备份 + 导出（安全底线）
5. 面经聚合视图 + promote CTA（沉淀闭环）
6. 简历深挖补齐（差异化）
