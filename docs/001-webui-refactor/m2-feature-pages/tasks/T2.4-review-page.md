# T2.4 · `/review` 页面重构（保留骨架 + 新密度重绘）

## 目标

按 `design.md §9 P4` + `roadmap.md §5.2` 对 `/review` 进行布局重构：
1. 保留 Header + 列表 / 详情两层骨架，按 M1 新密度策略（Header 紧凑 / Body 平衡）和新组件重绘——模式同 P3 `/questions`
2. 清理旧 token 类名 72 处 / 6 文件（见 §涉及文件）
3. 消费 M1 原子组件（`Card` / `Badge` / `Button` / `Dialog` / `PageHeader` / `EmptyList` / `DetailGrid` / `PlaceholderTable`），杜绝 inline 样式 hack

## 轻量 Design Note（5 项最小覆盖）

> 本段即 `/review` 页面的轻量 design note。

### 1. 目标

让用户进入 `/review` 时感知"这是一个面经审阅 / 处理队列"：顶部紧凑 Header + 下方审阅队列（review-queue）或单条审阅详情（review-job）。节奏偏"中性列表 + 详情展开"——与 P3 `/questions` 相似的 CRUD 列表体验，但增加了"导入预览 → 确认 → 处理"的 action 流程。

### 2. 布局骨架

**队列视图（review-queue-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title="面经审阅" + actions(刷新 Ghost)   |
+------------------------------------------------------------+
| 审阅队列                                                    |
|  +------------------------------------------------------+  |
|  | ReviewJobCard (Card)                                   |  |
|  |  · 标题 + Badge(状态) + meta(来源/创建时间)            |  |
|  |  · 点击进入 review-job 详情                           |  |
|  +------------------------------------------------------+  |
|  | ReviewJobCard × N                                      |  |
|  +------------------------------------------------------+  |
|  | EmptyList (队列为空)                                   |  |
|  +------------------------------------------------------+  |
+------------------------------------------------------------+
```

**详情视图（review-job-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title={job标题} + actions(操作按钮组)    |
+------------------------------------------------------------+
| 导入预览区 (review-import-preview.tsx)                      |
|  · 预览内容展示                                              |
|  · 操作按钮在 PageHeader 或底部 action bar                   |
+------------------------------------------------------------+
| 确认对话框 (review-confirm-dialog.tsx)                      |
|  · Dialog: footer 右下 Primary "确认" + Secondary "取消"    |
+------------------------------------------------------------+
```

- **队列视图**：与 P3 `/questions` 同模式——PageHeader + 卡片列表
- **详情视图**：PageHeader + 预览主区 + action buttons + Dialog 确认流
- **响应式**：< 768px 卡片全宽，预览区单列

### 3. 按钮摆放

- **队列 PageHeader 右上**：1 个 Ghost "刷新"（sm），无 Primary（队列是被动消费）
- **详情 PageHeader 右上**：1 个 Primary "处理"（lg），开始该条审阅的主操作
- **详情 action bar**：Secondary "跳过" + Destructive "拒绝"；不与 Primary 并排（Primary 在 PageHeader）
- **Dialog footer**：右下 Primary "确认" + 左侧 Secondary "取消"（对齐 `design-system.md §2` Dialog 规则）
- **空态**：`EmptyList` 标题"审阅队列为空" + Link "导入新面经"

### 4. 空态

- **审阅队列为空**：`EmptyList` 标题"审阅队列为空" + Link "导入新面经"（跳转 `/import`）
- **Placeholder 态**：`review-job-placeholder.tsx` / `review-queue-placeholder.tsx` 消费 `Skeleton` / `PlaceholderTable` 做骨架屏
- **不引入插图**（延续全 phase 决策）

### 5. 明确不做

- **不动**：业务逻辑（review job CRUD / 审阅流程 / `review-shared.ts` 共享类型 / server calls 不变）
- **不引入**：新装饰元素 / 新色阶 / 新圆角值
- **不引入**：批量操作 / 高级筛选等新功能

## Step 3 · 写最小实现

按 §轻量 Design Note 重写 `src/features/review/*`：

1. **清旧 token 类名**（6 文件 72 处）：
   - `border-border-strong` / `border-border-muted` → `border-[color:var(--color-border)]`
   - `text-text-muted` → `text-[color:var(--color-muted-foreground)]`
   - `text-text-strong` → `text-[color:var(--color-foreground)]`
   - `bg-accent` → `bg-[color:var(--color-brand-soft)]`
   - `text-accent` → `text-[color:var(--color-brand)]`
2. **队列视图密度重绘**（`review-queue-workbench.tsx`）：
   - `PageHeader` 紧凑档：`title="面经审阅"` + actions（Ghost "刷新" sm）
   - 卡片列表消费 `Card` / `Badge`；hover `hover:border-[color:var(--color-brand)]`
   - 空态消费 `EmptyList`
3. **详情视图密度重绘**（`review-job-workbench.tsx`）：
   - `PageHeader` 紧凑档：`title={job标题}` + actions（Primary "处理" lg）
   - 内容区消费 `Card` / `DetailGrid`
4. **Dialog 消费**（`review-confirm-dialog.tsx`）：
   - 消费 M1 `Dialog` 组件：`<Dialog>` + `<DialogContent>` + `<DialogHeader>` + `<DialogFooter>`
   - footer 按钮：右下 Primary "确认" + Secondary "取消"
5. **Placeholder 消费**（2 个 placeholder 文件）：
   - 消费 `Skeleton` / `PlaceholderTable`，去旧 token

实施时严格参考 `docs/reference/design-system.md §2 按钮摆放规则` + `§4 原子组件 API`。
