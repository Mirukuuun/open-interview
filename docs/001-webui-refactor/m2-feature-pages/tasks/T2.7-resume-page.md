# T2.7 · `/resume` 页面重构（最复杂 · 启动前判定是否升级 design doc）

## 目标

按 `design.md §9 P7` + `roadmap.md §5.2` 对 `/resume` 进行布局重构：
1. `/resume` 结构在 7 页中最复杂（简历 + 项目 + 深挖会话三层嵌套关系），需在启动前独立判定是否需要升级为独立小 design doc
2. 清理 M1 已知 cosmetic 退化：
   - `interactive-card` 5 处（`resume-workbench.tsx:125,162` / `resume-detail-workbench.tsx:56` / `project-workbench.tsx:118` / `project-session-workbench.tsx:158`）
   - 旧 token 类名 81 处 / 10 文件（见 §涉及文件）
3. 消费 M1 原子组件，杜绝 inline 样式 hack

> **启动前决策点（对应 `roadmap.md §5.5` R4 风险）**：T2.7 启动时，执行人先审查当前 `/resume` 的结构复杂度，判定是否将本 task 拆分为 T2.7a（design note 升级为独立小 design doc）+ T2.7b（实现）。若不需要升级，则沿用本 task 的轻量 design note 直接实施。此决策不阻塞 T2.1–T2.6 合入。

## 轻量 Design Note（5 项最小覆盖）

> 本段为默认的轻量 design note。若启动前决策判定需升级，则另开独立 design doc 替代本段。

### 1. 目标

让用户进入 `/resume` 时感知"这是一个简历管理 + 项目深挖工作台"：简历概览 → 项目列表 → 项目深挖会话，三层导航清晰。节奏为"渐进展开"——从概览逐步深入到细节，每一层有自己的主视觉焦点。

### 2. 布局骨架

**简历列表（resume-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title="简历" + actions(添加简历 Primary) |
+------------------------------------------------------------+
| 简历卡片列表                                                |
|  +------------------------------------------------------+  |
|  | ResumeCard (Card)                                      |  |
|  |  · 简历名 + Badge(状态) + meta(更新时间)               |  |
|  |  · 项目数 badge                                        |  |
|  |  · 点击进入 resume-detail                              |  |
|  +------------------------------------------------------+  |
|  | ResumeCard × N                                         |  |
|  +------------------------------------------------------+  |
|  | EmptyList (0 份简历)                                   |  |
|  +------------------------------------------------------+  |
+------------------------------------------------------------+
```

**简历详情（resume-detail-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title={简历名} + actions(编辑 Secondary) |
+------------------------------------------------------------+
| 简历信息 (DetailGrid / Card)                                |
+------------------------------------------------------------+
| 项目列表 (SectionHeading "项目")                            |
|  · ProjectCard × N — 点击进入 project-workbench            |
|  · EmptyList (0 个项目)                                     |
+------------------------------------------------------------+
```

**项目详情（project-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title={项目名} + actions(深挖 Primary)   |
+------------------------------------------------------------+
| 项目信息 (DetailGrid / Card)                                |
+------------------------------------------------------------+
| 深挖会话列表 (SectionHeading "深挖会话")                     |
|  · SessionCard × N — 点击进入 project-session               |
|  · EmptyList (0 条会话)                                     |
+------------------------------------------------------------+
```

**深挖会话（project-session-workbench.tsx）**：
```
+------------------------------------------------------------+
| PageHeader (紧凑): title={会话标题} + actions               |
+------------------------------------------------------------+
| 对话流 (单列气泡流，复用 T2.2 的气泡风格)                    |
|  · AI 提问左对齐 + 用户回答右对齐                            |
|  · deep-dive-answer-form.tsx 底部输入区                     |
+------------------------------------------------------------+
```

- **三层嵌套**：resume → project → session，每层有自己的 PageHeader + 内容区
- **响应式**：< 768px 全部单列堆叠

### 3. 按钮摆放

- **简历列表 PageHeader 右上**：1 个 Primary "添加简历"（lg）
- **简历详情 PageHeader 右上**：1 个 Secondary "编辑"（sm）
- **项目详情 PageHeader 右上**：1 个 Primary "开始深挖"（lg，链到 start-deep-dive-session-button 的功能）
- **深挖会话输入区**：1 个 Primary "发送"（md）
- **每张卡片**：无按钮，整卡可点击；hover `hover:border-[color:var(--color-brand)]` 替代旧 `.interactive-card`
- **`start-deep-dive-session-button.tsx`**：保持其现有逻辑不动（`files_readonly`），仅确保消费的 Button 组件兼容

### 4. 空态

- **简历列表为空**：`EmptyList` 标题"还没有简历" + `xl` Primary "添加简历" + Link "了解简历功能"
- **项目列表为空**：`EmptyList` 标题"还没有项目" + `xl` Primary "添加项目"
- **深挖会话列表为空**：`EmptyList` 标题"还没有深挖会话" + `xl` Primary "开始深挖"
- **Placeholder 态**：4 个 placeholder 文件消费 `Skeleton`
- **不引入插图**（延续全 phase 决策）

### 5. 明确不做

- **不动**：业务逻辑（简历 / 项目 / 深挖会话的 CRUD / AI 调用 / streaming / server calls 不变）
- **不动**：`start-deep-dive-session-button.tsx` 的交互逻辑（仅读取确认 Button 消费兼容）
- **不动**：`resume-source-panel.tsx` 的业务逻辑（仅做旧 token 类名替换）
- **不引入**：新装饰元素 / 新色阶 / 新圆角值
- **不引入**：简历编辑 / 项目拖拽排序等新功能
- **深挖会话气泡风格**：复用 T2.2 `/qa` 确立的单列气泡模式，不另起设计

## Step 3 · 写最小实现

按 §轻量 Design Note 重写 `src/features/resume/*`：

1. **去 `interactive-card`**（5 处）：所有 `interactive-card` 类替换为 `hover:border-[color:var(--color-brand)] transition-colors`；保留既有 `rounded-*` / `border` / `px-* py-*` 等几何表达
2. **清旧 token 类名**（10 文件 81 处）：
   - `border-border-strong` / `border-border-muted` → `border-[color:var(--color-border)]`
   - `text-text-muted` → `text-[color:var(--color-muted-foreground)]`
   - `text-text-strong` → `text-[color:var(--color-foreground)]`
   - `bg-accent` → `bg-[color:var(--color-brand-soft)]`
   - `text-accent` → `text-[color:var(--color-brand)]`
3. **简历列表布局**（`resume-workbench.tsx`）：
   - `PageHeader` 紧凑档：`title="简历"` + Primary "添加简历"（lg）
   - 卡片列表消费 `Card` / `Badge`；hover `hover:border-[color:var(--color-brand)]`
   - 空态消费 `EmptyList`
4. **简历详情布局**（`resume-detail-workbench.tsx`）：
   - `PageHeader` 紧凑档 + Secondary "编辑"
   - 消费 `DetailGrid` / `Card` + `SectionHeading` "项目"
5. **项目详情布局**（`project-workbench.tsx`）：
   - `PageHeader` 紧凑档 + Primary "开始深挖"
   - 消费 `DetailGrid` / `Card` + `SectionHeading` "深挖会话"
6. **深挖会话**（`project-session-workbench.tsx`）：
   - 单列气泡流（复用 T2.2 确立的模式：AI 提问左对齐 / 用户回答右对齐）
   - `deep-dive-answer-form.tsx` 底部输入区
7. **Placeholder 文件**（4 个）：消费 `Skeleton`，去旧 token
8. **来源面板**（`resume-source-panel.tsx`）：去旧 token 类名
