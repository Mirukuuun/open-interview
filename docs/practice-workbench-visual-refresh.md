# Open Interview 练习工作台视觉收缩与布局重构设计

- doc_type: design_doc
- status: proposed
- updated_at: 2026-04-03
- scope: `src/components/workbench/*`、`src/features/practice/*`、`src/features/workbench/*`
- canonical_for: 练习页视觉收缩、全站说明文案删减、左侧导航收起交互
- target_platform: desktop only

## 1. 背景

当前 workbench 已具备完整功能，但界面存在以下共性问题：

- 页面标题、统计卡和区块标题整体偏大，首屏重量过高。
- 解释型文案过多，头部和模块内部存在大量“介绍 / 说明 / 产品解释”句子，稀释核心操作。
- `/practice` 页面把长期能力画像、最近考试、训练方式等内容堆在左侧长栏中，纵向过长，视觉失衡。
- 左侧一级导航持续占据较大横向空间，在练习、考试、QA 等需要聚焦的页面中显得臃肿。

本次设计目标不是增加装饰，而是做一次系统性的“收缩”：

- 收紧排版
- 删除解释文案
- 重排练习页信息结构
- 为工作台提供可收起的导航形态

## 2. 设计目标

### 2.1 总目标

让界面从“偏重的 dashboard / admin 风格”收敛为更克制、更专注的面试工作台。

### 2.2 具体目标

- 所有页面标题更小、更轻、更干净。
- 页面只保留必要的信息：标题、状态、数据、动作。
- `长期能力画像` 保持高优先级，但不再以左侧长栏的方式出现。
- `/practice` 的首屏要先表达“我现在能做什么、我的长期水平如何、下一步做哪种练习”，而不是先看到一列冗长摘要。
- 左侧导航在桌面端支持收起，释放主舞台空间。

## 3. 设计原则

### 3.1 去介绍化

删除所有产品介绍、说明性、解释性文案。页面不再承担“介绍产品”的职责，只承担“帮助用户执行当前任务”的职责。

保留：

- 标题
- 状态
- 数据
- 动作
- 功能必要提示
- 空态 / 错误 / 加载反馈

删除：

- 页面头部说明句
- 区块说明句
- 图表解释句
- “训练方式”类说明卡
- “从导入、审核到练习与 grounded QA...” 这类产品介绍句

### 3.2 聚焦主任务

`/practice` 的主任务是开始练习、进入考试、查看当前题目、回看结果。任何不直接支撑这些动作的信息都必须下沉或压缩。

### 3.3 保留核心资产

`长期能力画像` 不是附属信息，而是练习模块的核心资产。它需要被保留为高优先级内容，但应以内聚、紧凑的方式呈现，而不是展开成一整列长模块。

### 3.4 工作台优先

页面应该更像“专业陪练台”，而不是“数据后台”。视觉语言应冷静、可信、克制，不做额外叙事，不做大面积说明。

## 4. 范围

### 4.1 本次纳入

- 共享 `PageHeader` / `SectionHeading` 的视觉收缩
- `/practice` 页面布局重构
- `/practice` 中长期能力画像与最近考试模块的重排
- 左侧一级导航的可收起交互
- 全局解释型文案的删减策略

### 4.2 本次不纳入

- 数据模型、API 契约、服务逻辑变更
- 练习 / 考试流程业务规则变更
- 全站彻底重做主题色和字体体系
- 移动端设计与适配

## 5. 全局设计规范调整

### 5.1 标题层级

建议统一收紧标题尺寸：

| 角色 | 当前倾向 | 目标建议 |
| --- | --- | --- |
| 页面主标题 | 偏大 hero | `24px - 28px`，`semibold` |
| 一级区块标题 | 偏醒目 | `16px - 18px`，`semibold` |
| 普通重点数字 | 常用 `text-2xl` | `18px - 20px` |
| 正文 / 说明 | `14px - 15px` | 保持不变或略收紧 |
| 元信息标签 | 多个 mono 大写标签 | 减少使用频率 |

要求：

- 页面主标题不再默认使用 hero 气质。
- 普通统计信息不再通过超大数字建立层级。
- 区块标题与标题之间通过间距和分组体现层级，不依赖大字号堆叠。

### 5.2 说明文案策略

全站默认不展示 `description` 型文案。

替代方式：

- 用状态条替代说明句
- 用轻量统计条替代解释段落
- 用空态 / 错误态承担必要提示

例如：

- 保留：`当前按 Java 基础定向练习`
- 删除：`当前按「Java 基础」定向练习；随机练习和模拟考试都会只使用该维度映射到的题目。`

### 5.3 容器重量

建议同步收紧容器表现：

- 大圆角收紧
- 渐变减弱
- 阴影变浅
- 减少“卡片里再套卡片”的层级感

方向上保留现有浅色工作台气质，但去掉过重的 hero 头部和层叠卡片视觉。

## 6. `/practice` 页面重构

### 6.1 重构目标

解决以下问题：

- 左侧长栏过长
- 顶部信息过重
- 长期能力画像位置不合理
- 最近考试与练习主舞台争夺首屏空间

### 6.2 新的信息优先级

`页面总览 -> 当前动作 -> 历史记录`

对应到页面：

1. 页面总览：随机练习主卡
2. 当前动作：练习 / 考试主舞台
3. 历史记录：最近考试

### 6.3 新布局结构

桌面端建议结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部主卡：随机练习                                            │
│  标题 / 模式切换                                              │
│  统计条                                                       │
│  长期能力画像（并入主卡底部）                                  │
└──────────────────────────────────────────────────────────────┘

┌────────────────────────────────────┬─────────────────────────┐
│ 左：主舞台                         │ 右：最近考试            │
│ 开始练习 / 当前题目 / 考试作答 /    │ 2-3 条紧凑记录          │
│ 考试结果                            │ 查看更多                │
└────────────────────────────────────┴─────────────────────────┘
```

补充线框：顶部主卡三层结构

不再保留固定的左侧长摘要栏。本版只定义桌面端。

### 6.4 顶部主卡

`长期能力画像` 并入 `随机练习` 主卡底部。

主卡分三层：

#### 第一层：标题与模式切换

保留：

- `随机练习`
- `随机练习 / 模拟考试` 切换

删除：

- 所有介绍性说明句

#### 第二层：统计条

建议保留 4 项：

- 题池数量
- 可评分题数量
- 最近考试数
- 当前范围

表现形式：

- 单行轻量 meta strip
- 或紧凑 4 项小块
- 不使用过大的 hero 数字

#### 第三层：长期能力画像

画像作为主卡底部的核心内容，而非独立侧栏。

### 6.5 长期能力画像模块

#### 位置

放在 `随机练习` 主卡最底部。

#### 呈现结构

桌面端：

- `2 列 x 3 行`

每个维度项只保留：

- 维度名
- 分数
- 细进度条
- 轻量入口或高亮状态

删除：

- 每个维度完整的大按钮区
- 每个维度独立的大卡片结构
- 冗长的解释文字

保留：

- 最近评估时间
- 当前定向维度高亮
- 最弱维度的练习入口

交互建议：

- 当前定向维度高亮显示
- 行尾可放轻量链接或 chip
- 不要求每个维度都占用完整按钮区

状态规格：

- 未开始练习：显示完整 `2 列 x 3 行` 画像，每项保留维度名、分数、细进度条、轻量入口。
- 随机练习中：仍显示 6 维，但切成紧凑版；移除每项入口，只保留维度名、分数、4px 细条和当前维度高亮。
- 模拟考试作答中：沿用紧凑版，不再展示额外入口或辅助说明。

紧凑版定义：

- 仍为 `2 列 x 3 行`
- 每项只占一行半左右的高度
- 不显示大按钮
- 不显示解释文字
- 保留 `最近评估` 一行元信息

顶部主卡视觉高度目标：

- 未开始练习：完整展开，高度以容纳三层内容为准
- 随机练习中：压缩为完整态的中等高度
- 模拟考试作答中：进一步压缩，但仍保留 6 维紧凑画像

建议实现时以“同一屏内尽量完整看到主卡与主舞台起始区”为目标，而不是追求单一固定像素值。

### 6.6 最近考试模块

从左侧长栏迁移到主舞台旁的次级区域。

规则：

- 默认只展示最近 `2-3` 条
- 每条信息压缩为紧凑列表项
- 保留：分数、时间、薄弱项、弱项快捷入口
- 删除：过大的分数字号和过厚的卡片表现

目标是让它成为“可快速扫读的历史区”，而不是另一块抢视觉的主内容。

### 6.7 主舞台

主舞台承担所有当前任务：

- 开始随机练习
- 当前题目
- 揭晓答案
- 开始模拟考试
- 考试作答
- 考试结果与反馈

要求：

- 作答态优先单栏聚焦
- 次级信息不应继续与作答区争抢视觉注意力
- 结果页允许重新展开更多分析内容，但首屏仍先看总分与关键反馈

### 6.8 定向练习状态

`当前定向维度` 不再独立占一张卡。

改为主卡中的状态条：

- 显示当前维度
- 显示已过滤状态
- 提供 `退出定向练习`

要求：

- 只占一行
- 不重复解释过滤机制

### 6.9 状态切换线框

未开始练习：

```text
[完整主卡]
  标题 / 切换
  统计条
  完整 2x3 长期能力画像

[主舞台入口]
[最近考试]
```

随机练习中：

```text
[压缩主卡]
  标题 / 切换 / 统计条
  紧凑版 2x3 长期能力画像

[当前题目主舞台]
[最近考试]
```

模拟考试作答中：

```text
[最紧凑主卡]
  标题 / 当前模式 / 统计条
  紧凑版 2x3 长期能力画像

[考试作答主舞台]
```

## 7. 删除型文案规范

以下类型的文案统一删除：

- 页面头部描述
- 区块说明文字
- 图表描述文字
- 流程解释文字
- “为什么这样设计 / 这个模块做什么”的介绍句

以下类型的文案保留：

- 按钮文案
- 空态说明
- 错误提示
- 加载提示
- 题目内容
- 评分反馈
- 必要状态提示

实现上建议：

- 默认组件不再依赖 `description`
- 允许个别高风险状态单独保留必要提示

## 8. 左侧导航栏可收起设计

### 8.1 目标

缓解工作台整体横向拥挤问题，为练习、考试、QA 等主舞台页面释放空间。

### 8.2 桌面端两种状态

#### 展开态

- 保持现有完整导航
- 显示品牌、图标、文字、badge

#### 收起态

- 宽度缩到窄栏
- 只保留图标
- 当前页面高亮仍然明确
- hover / focus 显示 tooltip

建议宽度：

- 展开：现有宽度
- 收起：约 `64px - 72px`

补充线框：导航收起态

```text
展开态                          收起态
┌──────────────┐               ┌────┐
│ Open Interview│               │ OI │
│ [<]          │               │ [>]│
│              │               │    │
│ 图标  导入    │               │ ⌂  │
│ 图标  审核    │               │ ✓  │
│ 图标  题库    │      ->       │ ≡  │
│ 图标  练习    │               │ ▶  │
│ 图标  QA      │               │ ?  │
└──────────────┘               └────┘
```

### 8.3 交互位置

收起按钮放在左侧导航顶部、品牌区附近。

要求：

- 不喧宾夺主
- 点击后状态立即生效
- 状态持久化保存

### 8.4 状态策略

建议：

- 首次访问统一展开
- 记住用户上次选择
- 只有用户手动收起后才持久化该偏好
- 不做“首次进入自动收起”
- 用户一旦收起，在路由切换后继续沿用该选择

### 8.5 视觉规则

收起后仍需保留：

- 一级导航图标
- active 态
- review badge 的简化表达

badge 规则：

- 展开时显示正常 badge
- 收起时转为小圆点或简化数字

### 8.6 动效与过渡

只保留轻过渡，不做明显动画表演。

适用范围：

- 导航展开 / 收起
- 顶部主卡压缩 / 展开
- 长期能力画像从完整态切到紧凑态

建议：

- 时长：`180ms - 240ms`
- 缓动：`ease-out`
- 过渡属性以尺寸、透明度、间距为主
- 不引入复杂入场动画
- 遵循 `prefers-reduced-motion`

## 9. 状态切换策略

### 9.1 未开始练习

顶部主卡完整展开：

- 标题
- 模式切换
- 统计条
- 完整长期能力画像

### 9.2 随机练习中

顶部主卡压缩：

- 保留标题与统计
- 长期能力画像变成紧凑版 `2 列 x 3 行`
- 主舞台优先

### 9.3 模拟考试作答中

进一步压缩顶部主卡：

- 只保留必要状态
- 长期能力画像保持紧凑版 `2 列 x 3 行`
- 把注意力让给考试作答区

### 9.4 考试结果页

结果页允许重新展开更多分析内容：

- 总分
- 整体反馈
- 本次考试雷达
- 长期能力画像
- 逐题反馈

但结果首屏仍然应先突出总分与关键反馈，不应先看到长篇说明和次级信息。

## 10. 验收标准

满足以下条件可视为设计目标达成：

- 全站页面头部不再出现解释型文案。
- `/practice` 首屏不再出现固定左侧长摘要栏。
- `长期能力画像` 被并入顶部主卡底部，未开始时完整展示，练习 / 考试时切为紧凑版。
- 紧凑版画像仍然保留 6 个维度的小条，不丢失维度全貌。
- `最近考试` 变成紧凑次级区，不再占据一整列长卡片。
- 左侧导航在桌面端可展开 / 收起，且首次访问默认展开。
- 导航一旦被用户手动收起，状态在后续访问中可记忆。
- 页面整体视觉应明显比当前版本更轻、更短、更聚焦。

## 11. 实施建议

建议按以下顺序落地：

1. 收紧共享 `PageHeader` / `SectionHeading`
2. 删除全局解释型文案
3. 重构 `/practice` 页整体布局
4. 将 `长期能力画像` 并入顶部主卡
5. 压缩 `最近考试`
6. 增加左侧导航收起能力

这样可以先解决“整体太大”的问题，再解决 `/practice` 的结构问题，最后释放全局横向空间。
